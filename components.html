AeroSense · components

Every part, and what it does.

AeroSense is a handheld reader and a throw-away cartridge. This page walks through each part of the hardware and each layer of the software, from the moment someone blows into the mouthpiece (or presses a fingertip on the pad) to the result on the screen and the record in the app.

01 · hardware

What's in the box.

Grouped by the job each part does. Parts that touch the breath live in the disposable cartridge. Everything else stays in the reader.

ASampling: the disposable cartridge

A1

Mouthpiece

single-use

The person blows through it. It bends down into the chamber so the breath goes straight at the nozzle. It's thrown away after each test, so nothing passes between people.

A2

Venturi nozzle

1.2 mm slit

Speeds the breath into a jet aimed at the gel from 2 mm away, then turns it sharply. Gas follows the turn and leaves; the heavier 0.5–5 µm droplets can't turn in time and land in the gel.

A3

Screen-printed electrode

2 × WE · RE · CE

Carbon strip with two working electrodes (a control and a sensing one), an Ag/AgCl reference and a carbon counter. The sample is measured right where it lands.

A4

Pre-cast hydrogel pad

agarose + saline + probe

A thin gel cast onto the strip and sealed in foil: about 1% agarose, 0.9% saline and a ferri/ferrocyanide redox probe. The sample merges straight into it, so no liquid is ever added in the field.

A5

Touch pad + sliding cover

touch mode

The front of the cartridge exposes the same gel pad behind a sliding cover. If someone can't or won't blow, the cover slides aside and a fingertip rests on the gel for 5–10 seconds.

BSample checks

B1

Differential pressure sensor

MPXV7002DP

Measures breath flow and adds it up into exhaled volume. Below the 1.5 L gate, no breath result is given and the reader asks for Touch mode.

B2

Capacitive touch ring

ESP32 touch pin

An electrode ringing the pad. A fingertip changes its capacitance, so the ESP32 knows contact is real and held for the full 5–10 s. Lift early and the result is Inconclusive.

CMeasurement and control

C1

Potentiostat front-end

DAC + op-amps + ADC

Sweeps a voltage across the strip and measures the tiny currents that come back. That current-vs-voltage curve (a voltammogram) is the raw data the classifier reads.

C2

ESP32 controller

NodeMCU-32S

The brain. It runs the test sequence, drives the potentiostat, cleans up the curve and runs the ML model on the device. Built-in Wi-Fi and Bluetooth handle syncing.

DInterface

D1

0.96″ OLED display

status + result

Shows each step (ready, blow, analysing), the breath-volume bar, the curve and the final result.

D2

Result LEDs

red · amber · green

Abnormal, inconclusive and normal. Readable at a glance, with no training.

D3

Start button + buzzer

one-button flow

One press starts a test. The buzzer confirms each step so the officer doesn't have to watch the screen.

EPower

E1

18650 Li-ion cell

rechargeable

Sized to last a full shift of roadside or clinic testing.

E2

TP4056 charger + regulator

USB-C

Charges the cell safely over USB-C and gives the electronics a steady supply, so readings don't drift as the battery drains.

E3

Mesh nebulizer

demo only

Makes a fine saline aerosol with safe surrogate compounds, so we can test the whole pipeline without any controlled substance.

02 · signal path

From one breath to one answer.

Flow or touch check

A deep breath (≥ 1.5 L), or a fingertip held 5–10 s on the pad.

Into the gel

Droplets or sweat merge into the pre-cast hydrogel on the electrode.

Voltammetry

A DPV sweep reads the redox probe. Blocked carbon means a lower peak.

Classify

The on-device model reads the curve and shows a result.

03 · software

Four layers, all running on the device.

Only the last layer needs a network, and the device doesn't need it to give a result.

L1

Firmware

C++ on FreeRTOS. A state machine runs each test: READY → BASELINE → BLOW (or TOUCH) → CAPTURE → MEASURE → ANALYSE → RESULT. It won't move on until the step before it has passed, such as enough breath volume or a held touch.

L2

Measurement routines

Differential-pulse and square-wave voltammetry (DPV / SWV) sweeps from −0.2 to +0.6 V, run by the ESP32 through the potentiostat. One baseline sweep when the strip goes in, one after the sample.

L3

Signal processing

Baseline correction and smoothing, then the control electrode is subtracted (ΔI = I(WE2) − I(WE1)). Features come from the cleaned curve: peak position, peak height, area under the peak, peak width and the slope around it.

L4

On-device ML + sync

The classifier turns those features into Reference (≥ 20 µA), Abnormal (≤ 10 µA) or Inconclusive. When a network is available, the record is sent to the IoT app.

04 · machine learning

Random Forest now. 1D-CNN when the data is ready.

Locked for the prototype

Random Forest classifier

Many small decision trees each vote on the curve's features, and the majority wins. The share of trees that agree becomes the confidence score.

Works with small data

Early on we'll have tens to a few hundred curves. Random Forests hold up well on small datasets where a deep network would overfit.

Fits the features we have

Peak position, height and area are exactly the kind of structured features trees handle best, with no scaling or tuning needed.

Tiny and fast

A trained forest is just a set of if/else comparisons. It compiles to plain C in a few kilobytes and runs on the ESP32 in milliseconds.

Honest confidence

If the trees don't agree strongly enough, the device shows Inconclusive instead of guessing.

Explainable

Feature importances show which parts of the curve drove a decision, which matters when a result is questioned.

Robust to noise

Averaging many trees smooths out one-off noise from a hand-held, field-used sensor.

The switch to a 1D-CNN

A 1D convolutional neural network reads the whole curve point by point instead of a handful of features. It can pick up overlapping peaks and small shoulders that fixed features miss, but it needs far more data to learn from.

  1. now

    Random Forest on curve features

    Locked. Trained on surrogate curves and runs on the device.

  2. while collecting

    Keep the raw curves

    Every test also saves the full resampled curve, so the CNN has training data waiting.

  3. trigger

    Enough data to switch

    Thousands of labelled curves across people, days and devices, tested on people the model has never seen.

  4. shadow mode

    Run both side by side

    The CNN runs silently next to the forest in the field. It takes over only once it beats the forest on held-out data and fits in memory.

  5. switch

    1D-CNN becomes primary

    Pushed to devices as a model update. The forest stays as a fallback.

05 · TinyML

Machine learning on a ₹400 chip.

TinyML means running a trained model on a microcontroller instead of a server. AeroSense gives its result with no network, no cloud and no phone, so the ML has to run on the device itself.

Train

On a laptop, in Python (scikit-learn for the forest, TensorFlow for the CNN).

Shrink

The forest is converted to plain C. The CNN is quantised to 8-bit integers, about 4× smaller.

Embed

The model is compiled into the firmware and flashed to the ESP32 (520 KB RAM, 4 MB flash).

Infer

Each curve is classified on the chip in milliseconds, fully offline.

Works anywhere

Roadsides, highways and rural checkpoints often have no signal. The result never depends on one.

Private by default

The breath curve is analysed on the device and never has to leave it to get a result.

Low power

A few milliseconds of computing per test barely affects the 18650's battery life.

06 · IoT app

The device decides. The app keeps the record.

An IoT companion app connects to readers over Wi-Fi or Bluetooth when a network is available. The device never waits for it. Records are queued on the device and synced later.
